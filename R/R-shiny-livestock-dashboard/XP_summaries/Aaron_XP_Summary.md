# Extreme Programming (XP) Summary

## Overview
Extreme Programming, also known as XP, is an Agile Process that focuses on rapidly developing high-quality software that provides the highest value for the customer. The 'Extreme' in XP relates to how it takes 12 well-known software development "best practices" to their logical extremes -- turning them all up to "10". It focuses on 4 key aspects to software development: Coding, Testing, Listening, and Designing.

## Core Practices
XP has 12 core practices:

- **The Planning Game**: business writes desired features as user stories, development estimates effort, and then business decides the order of user stories to implement, as well as the frequency of production releases
- **Small Releases**: start with useful features first, releasing frequently
- **System Metaphor**: project metaphors for a consistent naming convention
- **Simple Design**: keep design simple, only implement what is needed today
- **Continuous Testing**: tests before features, unit and acceptance tests ensure correctness, stories complete only when all tests pass  
- **Refactoring**: remove duplicate code, code remains functional because of tests
- **Pair Programming**: all code written in pairs, code is reviewed as it is written
- **Collective Code Ownership**: no individual ownership of a module, all developers are expected to be able to work on any part
- **Continuous Integration**: all changes integrated at least daily, all tests must pass before and after integration
- **40-Hour Work Week**: avoid overtime, consecutive weeks of overtime indicate something is wrong with the process
- **On-site Customer**: continuous access to live customer or customer proxy
- **Coding Standards**: same coding standards across all developers

## Extreme Roles

- **Tracker**: checks in with each developer at least weekly
- **Customer**: writes user stories and specifies functional tests
- **Programmer**: estimates the time it takes for tasks to be completed, and implements stories and tests
- **Coach**: watches over everything to make sure XP practices are followed
- **Tester**: implements functional tests, and makes sure the team knows if they fail
- **Doomsayer**: points out potential risks, making sure everybody understands them
- **Manager**: schedules meetings, records minutes and makes sure meeting processes are followed
