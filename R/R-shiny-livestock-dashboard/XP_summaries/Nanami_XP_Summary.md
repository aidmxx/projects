# Extreme Programming (XP) Summary

## Overview
Extreme Programming (XP) is an Agile software development methodology focused on high-quality code, rapid delivery, and the ability to adapt to changing requirements.

## Core Idea
XP takes proven software development best practices—like code reviews, frequent releases, and testing—and pushes them to the extreme. [1]

## Values
XP rests on five values:

- **Communication** – constant, open collaboration
- **Simplicity** – only build what's needed now
- **Feedback** – from tests, users, and teammates
- **Courage** – to refactor, admit mistakes, and change direction
- **Respect** – for people and their contributions [2]

## Practices
XP operationalises its values into 12 key practices:

- **Planning Game** – collaborative release and iteration planning using user stories
- **Small Releases** – frequent delivery of working software
- **On-Site Customer** – constant access to a real customer or representative
- **Pair Programming** – two developers work together at one workstation
- **Test-Driven Development** – write tests before writing code
- **Continuous Integration** – merge and test code frequently
- **Refactoring** – improve code structure continually
- **Simple Design** – build only what is essential now
- **Collective Code Ownership** – any team member can improve any code
- **Coding Standards** – consistent style for readability
- **Sustainable Pace** – avoid burnout
- **Metaphor** – a shared story or analogy for system design [3]

## Roles

- **Customer** – prioritises features, clarifies requirements
- **Developer** – implements stories and tests
- **Coach** – ensures XP values and practices are upheld
- **Tracker** – monitors progress and estimates
- **Tester** – focuses on acceptance and automated testing [4]
