# Extreme Programming (XP) Summary

## What is XP?
**Extreme Programming (XP)** is an **agile software development methodology** created by **Kent Beck** in the 1990s. It emphasizes a **transparent and accountable development environment** where:

- Developers **commit** to concrete goals.
- Progress is shown through **deployable software**.
- At milestones, the team explains **what was done**, **how it was done**, and **why it may differ** from the plan.

> *“XP is the practice and pursuit of effective simplicity, as applied to software development.”*

---

## XP Core Practices
XP is built on **12 core practices**, organized into **four categories**:

###  Fine-Scale Feedback
- **Test-Driven Development**
- **Planning Game**
- **Whole Team**
- **Pair Programming**

### Continuous Process (vs. Batch)
- **Continuous Integration**
- **Design Improvement**
- **Small Releases**

### Shared Understanding
- **Simple Design**
- **System Metaphor**
- **Collective Code Ownership**
- **Coding Standards**

### Programmer Welfare
- **Sustainable Pace**

---

## Roles in XP
XP defines several **team roles** to ensure clarity and accountability:

- **Tracker** → Checks progress weekly with programmers.
- **Customer** → Writes user stories & defines functional tests.
- **Programmer** → Implements features.
- **Coach** → Ensures XP practices are followed.
- **Tester** → Builds & runs functional tests.
- **Doomsayer** → Anticipates risks & issues ahead.
- **Manager** → Provides support & manages logistics.
